# 经验蒸馏与私有经验库

将一次已经完成且成功的交互，整理为可复用、可审查、可移植的候选经验；只在用户明确指定的私有 Git 仓库中处理。目标是保留可验证的方法与边界，而不是复述个人经历或收集敏感信息。

## 目录与边界

- 本 Skill 的 `references/`、`templates/`、`scripts/` 均相对此 Skill 目录读取；不得假定公共库或私有库的绝对路径。
- 只检查用户指定的私有库根及其范围内的内容；不要扩展扫描其他位置。
- 不读取、展示或写入凭据、Cookie、Token、API Key、真实个人数据、真实绝对路径、用户名、主机名或私人经历原文。
- 不自动创建远程仓库、push、安装其他工具或 Skill、修改用户级 Agent 配置。

## 安全停止条件

出现下列任一情况，立即停止写入与升格，说明原因并请求用户决定：

- 私有库根未明确；
- 目标路径不在用户明确允许的范围内；
- 内容疑似含凭据或真实个人数据；
- 候选与已有卡片冲突；
- 证据不足但仍被请求升格；
- 没有安全的写权限。

## 会话末尾协议

严格按以下顺序执行；不得跳步或把“建议”当作批准。

1. **显式调用与私有库根**：确认用户明确调用本 Skill 并提供私有库根。若缺少根路径，只询问该路径，不检索、不生成草案、不写入。
2. **只读检索去重**：仅在指定根内只读检索相近候选、经验卡、分类与索引，识别重复、冲突和可复用证据；不修改任何文件。
3. **敏感信息筛查**：逐项筛掉凭据、真实个人资料、真实机器或路径信息，以及不可安全泛化的经历细节。无法确定时按敏感处理并停止。
4. **候选草案与分类建议**：生成候选草案，并给出一个主分类建议：`experience`、`workflow`、`script`、`skill`、`agents_rule` 或 `memory_cache`。同时说明选择理由、仍需证据，以及一个备用分类。`memory_cache` 只能是指向已验证主资产的低敏感相对路径指针，绝不是事实来源，也不得独立承载经验内容。
5. **写前展示**：展示目标相对路径、去重/验证证据缺口、拟写内容和 `proposed_kind`；等待用户明确批准写入 `candidates/`。
6. **仅批准后写候选**：只有获得明确批准，才在用户指定私有库的 `candidates/` 中写入候选；若路径或范围不安全则停止。
7. **仅验证后升格**：候选只有在所列证据缺口已被验证、无冲突且用户允许的前提下，才能升格为相应主资产；证据不足时保留候选，不得升格。
8. **最后的可选 memory 指针**：全部完成后，至多提出一段可选建议：为已验证主资产添加一个低敏感相对路径 memory 指针。未经明确批准不写入，且不得把它当作事实源。

## 候选最小内容

候选应使用相对路径与去标识化叙述，至少包含：问题/触发条件、已验证做法、适用条件与限制、可复现步骤或检查点、证据来源的安全摘要、`proposed_kind`、分类理由、仍需证据、备用分类及隐私审查结果。若任一部分会暴露敏感信息，则改为安全概括；无法安全概括时停止。

## 分类准则

- `experience`：经审查后可复用的经验与判断，适用于相似情境。
- `workflow`：可重复执行的多步骤流程、检查点与回退方式。
- `script`：已验证的可移植自动化脚本或脚本说明；仅在无需敏感配置时采用。
- `skill`：可复用的 Agent 工作指引，包含触发条件、步骤与边界。
- `agents_rule`：适用于 Agent 的稳定行为规则或安全约束。
- `memory_cache`：仅保存已验证主资产的低敏感相对路径指针；不可替代上述任何主资产。

每次只能给出一个建议分类。若存在合理替代，明确列为备用分类，并写明为何不是主分类。

## 写入与升格检查

写入前复核：私有库根、目标相对路径、用户批准、去重结果、敏感筛查、证据缺口和写权限。升格前再复核：候选内容已验证、证据闭环、无冲突、目标类型符合分类准则，并获得所需批准。任何复核失败均停止，不以“后续补证”替代验证。

## 输出风格

正文以清晰简体中文说明；保留必要的路径、字段名和命令英文原样。始终区分已验证事实、推断、候选建议与待补证据；不要暗示未经学习、验证或批准的内容已经可靠或已写入。
